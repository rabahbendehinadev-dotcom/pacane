Act as a senior ERP architect and full-stack engineer.

Implement a new production-dispatch workflow in Pacane ERP:

ENVOI DE LA COMMANDE AUTOMATIQUE VERS LES OUVRIERS / CHEFS

This feature must transform the automatic replenishment / bon de commande calculation into real assigned preparation work orders for workers.

==================================================
BUSINESS CONTEXT
==================================================

We already have:
- products
- workers / responsables de préparation
- product -> worker assignment
- automatic replenishment / bon de commande page
- branch-specific stock target logic
- grouping/filtering by worker on the automatic replenishment page

Current limitation:
The automatic replenishment page only calculates needs and optionally groups them by worker.
But it does not yet create actual work orders for the assigned worker/chef.

Business need:
When the manager or responsible user calculates the "Commande automatique", they must be able to click:

"Envoyer aux ouvriers"

This action must create real preparation orders for each worker based on the calculated product needs.

Then:
- each worker / chef logs into the ERP with their own account
- they immediately see what they need to prepare
- they see only their own assigned preparation orders
- they can track progress with statuses

This turns the automatic replenishment system into a real operational dispatch workflow.

==================================================
CORE BUSINESS GOAL
==================================================

Build the following flow:

1. Automatic replenishment is calculated for a branch/date.
2. Products are grouped by responsible worker.
3. Manager clicks:
   "Envoyer aux ouvriers"
4. ERP creates one preparation order per worker.
5. Each worker sees only their own orders in a dedicated page.
6. Worker can update order status:
   - Nouveau
   - Vu
   - En cours
   - Terminé

IMPORTANT:
In this first version:
- these preparation orders are WORK ORDERS only
- they do NOT directly move stock
- they do NOT directly create production entries
- they do NOT change the replenishment math
- they are an assignment / execution layer above the automatic command page

PHASE 4 — SEND ACTION / ORDER GENERATION LOGIC
==================================================

When clicking "Envoyer aux ouvriers":

1. Recompute or verify the current calculation server-side
2. Group lines by worker_id
3. Create one preparation order per worker
4. Create preparation order items for that worker only
5. Save:
   - branch
   - worker
   - selected date
   - created_by
   - sent_at
   - initial status = new

Do NOT:
- move stock
- create production stock entries
- mark replenishment as completed
- create purchase documents
- create sales documents

This is only an execution/assignment workflow.

If duplicate sending is a risk:
- either allow multiple sends intentionally as separate orders
OR
- block exact duplicate send for same branch/date/worker/current result set

Recommended safe first version:
Before creating orders, detect if a non-cancelled preparation order already exists for:
- same branch
- same worker
- same source_replenishment_date
- same status not completed/cancelled
If so, show warning:
"Un ordre de préparation existe déjà pour cet ouvrier à cette date."
Offer either:
- cancel send
- or create anyway if business wants
For first version, safest is to block duplicates unless explicitly forced.
